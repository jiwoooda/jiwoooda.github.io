02 · From conversation to action

Maintaining task state across turns.

The agent carries product candidates, selected items, cart state, address/payment progress, and pending confirmations across a conversation. A session ID maps to LangGraph thread state for multi-turn continuity within the running service.

Discover need→Search→Rank / Select→Cart→Address→Payment confirmation→Order

Current commerce transactions use a mock backend. External search/MCP and Playwright integration paths exist, but production commerce deployment is not claimed here.

End-to-end product flow: onboarding and small talk → recommendation and cart → address confirmation → payment. The mobile UI was designed around a voice-first shopping journey for older adults.
03 · Reliability & safety

Keep the language flexible. Keep critical actions controlled.

Failure recovery

Transient retry with backoff, deterministic rerouting, fallback orchestration, constrained state recovery, source fallback, and graceful degradation.

Failure→Retry→Reroute→Recover

Transaction safety

Explicit HITL confirmation, product identity validation, address checks, pending-action guards, mock idempotency, and capability boundaries for unsupported post-order actions.

Failure-recovery design. Technical retry, search fallback, recovery, and graceful degradation are separated by failure type rather than handled by one generic fallback.
04 · Persona-based evaluation

Testing with the people the agent was designed for.

I designed and ran VIVID simulations to test whether older adults could understand, trust, and comfortably continue the shopping task—not just whether the model produced technically valid answers.

4 scenario types

Exploratory: vague greeting → natural onboarding
Direct: clear request such as “buy milk”
Ambiguous: “something to eat” → narrow within catalog
Topic deviation: health/loneliness/weather → return to shopping

Persona variation

Ages 65–80, balanced genders, different occupations and personalities, beginner-to-intermediate smartphone literacy, dialects, hesitant speech, and rambling conversational styles.

Primary signals

Trust · Frustration · Ease

Supporting metrics

Goal status · Empathy · Helpfulness · Clarification rate · Competence · Benevolence

VIVID diagnostic report from the initial evaluation. The important signal was not a single aggregate score: direct, ambiguous, and topic-deviation scenarios repeatedly broke down, while exploratory conversations performed better.
05 · What evaluation uncovered

Failures that happy-path development missed.

FAIL 01

Persona collapse during commerce

ObservedNatural conversational voice suddenly became fixed and mechanical during transactional steps.
Root causeDeterministic commerce flow used fixed messages and discarded prior conversational context.
FixKeep transaction logic deterministic while regenerating the surface response using user context.
Insight: deterministic logic does not require deterministic language.
FAIL 02

Unsupported products produced wrong selections

ObservedWhen a requested product/brand was unavailable, another item or catalog-external value could appear.
Root causeNo explicit edge-case policy existed for an unavailable requested product.
FixValidate product identity and explicitly recommend an available substitute instead of silently switching.
FAIL 03

Questions inside the payment flow

ObservedThe agent failed to answer shipping/payment questions while progressing through checkout.
Root causeThe original flow assumed users understood the system and would follow the expected happy path.
FixHandle informational questions while preserving the pending transaction state.
Evidence — cart removal. Across multiple sessions, requests to remove items were interpreted as additions. This exposed a missing action/capability rather than a simple wording problem.
Evidence — multi-turn breakdown. A virtual user asks about address and payment while correcting the cart; the agent loses the intended transaction context, and trust drops as frustration rises.
+ 3

Additional failures

Missing cart removal, inconsistent reset semantics, and recommendation clarification loops were also surfaced and addressed through capability, state, and response-flow changes.

06 · Failure-driven iteration

Evaluation should change the system.

Persona simulation→Failure transcript→Root cause→Structural fix→Regression asset

Recurring failures were translated into tests around product identity and substitution, clarification priority, missing-address payment guards, reset consistency, payment-question classification, and API compatibility. Separately, I built component-level evaluation data for intent, product, response, and context behavior.

An earlier LangSmith regression run for intent & slot routing improved from 83.3% to 100% after prompt refinement. This is a component-level result, separate from the later VIVID system evaluation.

07 · Model & recommendation design

Choose models and ranking logic by node requirements.

I evaluated model quality and latency at the node level rather than using one model everywhere, and designed recommendation ranking to combine user context, safety filters, and deterministic scoring.

Node-level model evaluation. Different quality metrics and latency trade-offs were used for intent, ranking, context construction, and response generation.
Recommendation pipeline. User context informs search and ranking, while explicit safety filters and code-based scoring constrain final candidate selection.
08 · Service interface & observability

Beyond the agent graph.

FastAPI bridge

/chat, /v1/chat/completions, and /v1/models, with session IDs, backward-compatible behavior, optional Bearer authentication, and sanitized errors on the OpenAI-style endpoint.

Structured debugging logs

Session/turn, intent, confidence, stage, pending action, routing, search source, ranking, payment events, retry/fallback, degradation, and final response are recorded for execution-path analysis.

The OpenAI-compatible endpoint supports a non-streaming chat subset. Persistent checkpoints, production deployment verification, CI/CD, and a unified real-time observability dashboard are future work.

09 · What I learned

Three principles I carry forward.

Agent failures are not always model failures.

Missing capabilities, state semantics, routing, and system assumptions can matter more than another prompt rewrite.

Deterministic control and LLM flexibility are complementary.

Safety-critical actions can remain explicit and testable while language and reasoning stay adaptive.

Evaluation is useful when it produces engineering changes.

Persona simulation became valuable when failures were traced, generalized, fixed, and preserved as reusable test assets.
